# 24. Implementation Policy

## Purpose

This document defines the implementation governance policy for the platform. It ensures that future work remains aligned with architecture, documentation, and constitutional requirements.

## Core Principles

- Architecture first.
- Documentation before code.
- The Constitution always wins.
- No implementation without documentation.
- No new module without approval.
- No new dependency without approval.
- No new technology without approval.
- No architectural changes without updating documentation.

## Policy Rules

### Architecture First

Implementation must follow the documented architecture. Technical work must not bypass architectural boundaries or governance principles.

### Documentation Before Code

Work must be documented before implementation begins. Documentation provides the basis for review, governance, and continuity.

### Constitution Always Wins

The Constitution remains the highest authority. Any conflicting request must be adapted or rejected.

### No Implementation Without Documentation

Implementation should not proceed without corresponding architecture or governance documentation.

### No New Module Without Approval

New modules must be introduced through the proper architectural review process.

### No New Dependency Without Approval

New dependencies must be governed and justified rather than introduced casually.

### No New Technology Without Approval

Technology choices must remain aligned with the platform’s principles and governance model.

### No Architectural Changes Without Updating Documentation

Any change to the architecture must be reflected in the documentation system.

## Future Expansion

This policy will remain active as the platform expands. It must be applied consistently to preserve the integrity of the architecture.
