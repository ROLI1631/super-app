# 05. Development Rules

## Purpose

This document defines the development standards that guide all future work on the platform. These rules preserve architectural quality, reduce duplication, and ensure that new work remains consistent with the system’s constitutional and architectural principles.

## Core Principles

- Write modular code.
- Keep responsibilities clearly separated.
- Never duplicate functionality when a shared abstraction is possible.
- Keep files small and focused.
- Reuse components and patterns where appropriate.
- Prefer composition over duplication.
- Document important decisions.
- Respect the established folder structure.
- Preserve modular boundaries.
- Never bypass the architecture to achieve short-term convenience.
- Maintain clarity over cleverness.

## Architectural Discipline

Development must be treated as an act of architectural stewardship. The goal is not merely to make something work, but to make it fit the system in a sustainable, maintainable, and governable way.

## Future Expansion Notes

As the platform grows, development discipline becomes more important. Expansion must remain coherent, documented, and consistent with the existing architecture rather than becoming a collection of isolated shortcuts.
